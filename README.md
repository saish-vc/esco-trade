# Esco Trade

A production-grade, provider-independent stock tracking and technical-analysis web application.

---

## Real-Time Market Data

Esco Trade implements a central **Server-Side Market Data Gateway** that decouples frontend clients from market data vendors. 

### Provider Adapters
1. **Demo Adapter (`demo`)**: Deterministic pseudo-random walk series for automated CI, local testing, and offline usage. Tagged as `SIMULATED`.
2. **Finnhub Adapter (`finnhub`)**: Real-time tick trade streaming via `wss://ws.finnhub.io`. Strict free-tier quota: 50 concurrent symbols, 1 active WebSocket connection.
3. **Alpaca Basic Adapter (`alpaca`)**: Real-time trade, quote, and minute bar streaming via `wss://stream.data.alpaca.markets/v2/iex`. Strictly limited to the Investors Exchange (**IEX only**, ~2-3% of US consolidated equity volume), with a maximum of 30 symbols concurrently.
4. **Polling Fallback (`polling`)**: Bounded REST polling with a 5-second clamp for environments where streaming sockets are interrupted or rate-limited.

### Data Classification & Integrity
The system enforces strict data honesty and never presents delayed, simulated, cached, or failed data as live:
- **`LIVE`**: Ticks received within `MARKET_DATA_STALE_AFTER_MS` (default 15s) from authorized streaming providers.
- **`SIMULATED`**: Synthetic ticks generated by the demo engine.
- **`DELAYED`**: Polled or REST-delayed feeds.
- **`STALE`**: Subscribed instruments with no incoming ticks for >15s during active market sessions.
- **`MISSING`**: Symbols unrecognized by the active provider.

### Architecture
- **Single Upstream WebSocket Connection**: Finnhub and Alpaca strictly disallow multiple connections per API key. The server manages a single upstream connection per configured provider.
- **Deduplication & Reference Counting**: When multiple browser clients subscribe to the same instrument (e.g. `AAPL`), only 1 subscription frame is sent upstream. Subscriptions are garbage collected when all clients disconnect.
- **Capacity Enforcement**: Hard quotas (Finnhub: 50, Alpaca: 30) are enforced server-side. Requests exceeding capacity are gracefully rejected with a visible capacity limit notice.
- **Candle Aggregator**: Real-time trade ticks roll into 1m, 5m, 15m, 1h, 1D candles aligned with session boundaries, updating Lightweight Charts without tearing down the chart view.

See [docs/market-data-providers.md](docs/market-data-providers.md) and [docs/realtime-architecture.md](docs/realtime-architecture.md) for sequence diagrams and entitlement details.

## Quick Start

### 1. Requirements
- Node.js 20+
- pnpm 9+
- PostgreSQL & Redis (running locally or via Docker)

### 2. Configure Environment
```bash
cp .env.example .env
```
Set `MARKET_DATA_PROVIDER=demo` (or `finnhub`/`alpaca` with your free API keys).

### 3. Database Migration & Seed
```bash
pnpm --filter @esco-trade/api exec prisma db push
pnpm db:seed
```

### 4. Run Development Servers
```bash
pnpm dev
```
- **Web UI:** http://localhost:3000
- **Fastify API:** http://localhost:4000 (Swagger docs at `/docs`)
- **WebSocket Gateway:** ws://localhost:4001

### 5. Run Test Suite
```bash
pnpm test
```
Runs Vitest across all workspace packages and integration suites.
